# Phase D — harness spec (2026-10-29)

Owns the *structure-aware fuzzing* phase of the T8103 program
(kickoff §8 + the Phase-C backlog additions H5/H6). Establishes the
shared emulation substrate, the six harness definitions as they stand
after Phases A–C, execution order, and the discipline rails.

This document is class-level and committable. All harness code,
corpora, triage logs and PoC artifacts are **side-local**
(`~/research/j407-bootchain/harness/`, PoCs default to
`research/poc-local/`) — push = publication rules unchanged.

## 1. Hard rules for Phase D

1. **No device.** Every harness runs host-side on macOS; "closest we
   get to the device" is emulation of bytes we already extracted.
2. Every crash gets the `crash → reproduce → minimal-case → verdict`
   loop; findings doc-first (Phase F), never tip-toe toward a
   deployable exploit chain.
3. Determinism: corpus items are files with SHA-256 in the ledger;
   every run is commanded from a fixed seed + fixed configuration;
   timers/rng seeded or disabled.
4. Coverage before volume: each harness ships an executed-coverage map
   (basic-block reachability within its target functions) — fuzzing
   breadth follows reachability, not trial counts.
5. Emulation faults that are *expected* (arguments a policy check
   rejects) are triaged separately from genuine crashes — the router
   (H5) proves policy checks exist; treat "guarded-reject" as a
   healthy outcome, not noise.

## 2. Shared substrate (`harness/`, side-local)

Two image maps feed all harnesses:

| Image | byte source (side-local) | VA frame | Notes |
|---|---|---|---|
| consolidated iBoot j407 | `raw_iBoot.j407.RELEASE` (2,255,320 B, canonical) | fileoff N → VA `0x1fc04c000 + N` | raw arm64 from offset 0, no Mach-O header (Phase B finding) |
| SPTM t8103 | `mac27-t8103-extracted/sptm.t8103.bin` (1,228,832 B) | VA = file + `0xfffffff027000000` | Mach-O; segment map in phase-C §5.1 |

Substrate (`emu.py`):
- Unicorn 2.1.4 (already present on host), AARCH64.
- Sysreg hooks: `MRS`/`MSR` intercepted; reads of the per-cpu context
  register return a pinned scratch block; undefined regs → fault floor.
- Exception behavior as *hooks*, not crashes: `BRK #0xc471`
  (the image's own guard assertion signature), SVC/HVC, WFI →
  deterministic stop with full register + memory-window dump.
- Constraint: only pages the harness pre-maps are readable; any other
  access is a hard, reportable fault (faults are data).
- Buffers in a pinned scratch arena independent of both image frames.
- One-command repro: `run.py <harness> <seed-id> [--config k=v…]`.

## 3. Harness definitions

### H1 — IMG4/Image4 parser cluster (consolidated iBoot)
- Target: parser state machine cluster in the consolidated image.
  Entry-function set to be pinned by a first Ghidra recon pass on the
  raw binary (`analyzeHeadless` with the BinaryImage loader at base
  `0x1fc04c000`, then filter decompile hits against the parser
  strings from the Phase-C identifier census) — **next unit**.
- Input space: container blobs — magic/version words, length fields,
  SEQ/property nesting depth & chunk tails, trust-cache leaf shapes.
  Seeds: replay of the recon §2 EP0 shapes (side-local artifacts;
  local-only TSV payload bytes stay local).
- Grammar mutations: length-field desyncs, truncated SEQ tails,
  oversized-nesting, mixed valid/invalid records.

### H2 — LZFSE/deco chain (consolidated iBoot)
- Targets (fileoffs; VA = K + off): decode entry `0xdc808`, decoder
  `0xddb10`, VLC-table region (delta-flagged), small-workspace
  selector path (near-offset `0x891` selector constant from prior
  pass).
- Input space: LZFSE bitstream-shaped blobs. Seeds generated by
  re-using real LZFSE streams already extracted during Phase B
  (side-local), then grammar-mutated: block-type field flips, chunk
  length-field desyncs, invalid final blocks, short tails.
- Vetted first because it is a self-contained function — the substrate
  smoke test rides this harness.

### H3 — registration/arg paths (consolidated iBoot)
- Targets: the `go` 9-byte key + `memboot` 4-char tag lookup paths and
  their object-registration upstreams (prior recon; entry fns pinned
  in the same Ghidra recon as H1).
- Input space: key-table mutations, tag shapes, registration-object
  ordering (list operations with adversarial nops/not-present cases).

### H4 — iBSS USB descriptor/request parsers
- Prereq: extract the iBSS personality (the consolidation finding
  proves the bytes are inside the consolidated image; a dedicated
  slice extraction is a small step once the personality offset map is
  confirmed).
- Input space: control-transfer record replays (setup packet shape,
  descriptor indices, string indexes, request phases) against the
  extracted parser, in emulation — class-level only; *live* probing of
  any USB parser belongs to Phase E behind the announcement rule.

### H5 — SPTM verb router (top priority; static milestones M1–M3 done)
- Frame: SPTM image map; per-cpu context blocks emulated per the
  decompile facts (context record + saved-register slots; sysreg read
  hook returns one).
- Drive: `fn@0xe8c24` (the router) directly with generated call words:
  `domain_id (8b @32) | flags (bits 6–7 = 0 legal / nonzero probes) |
  endpoint_id (6b @0)`.
- Enumerated tables (const, side-local `fid-table.md` + mode tables):
  SPTM-core FID table (40 declared rows, row index = FID), TXM-mode,
  SK-mode, HIB tables; per-domain registry shape at fileoff `0x09de68`.
- Legality oracle (checks *before* handler body): panic-state flag
  gates (bits0/1 row flags in states `0x14`/`0x16`) — the harness
  verifies handlers' own argument checks and behaves under
  state/permission combinations, subdividing into:
  row-flag conformance → unregistered-slot (`assert 0x31` path) →
  handler-body reach with benign args.
- Class-level only: no state-bypass intent; the value is
  correctness/robustness research on our extracted blob.

### H6 — delta-bounded corpora (all harnesses)
- Corpus family from the j407↔j408 delta regions (465,949 differing
  bytes, 51 merged regions — side-local `delta_audit` report) and the
  SPTM t8103↔t8112 deltas (10 regions): paragraph-level slices chosen
  at region boundaries + interiors, feeding H1/H2/H3 seeds as
  region-derived variants.

## 4. Execution order

1. **Substrate + smoke test** (this unit): `harness/emu.py`,
   map consolidated iBoot at K, call the H2 decoder on a small
   LZFSE-shaped buffer, record executed-treachery map & dump.
2. **H2** full corpus (small; self-contained).
3. **H1 Ghidra recon → harness** (parser cluster entry set).
4. **H5** sandbox (SPTM frame) — router enumeration, flag conformance.
5. **H3** register/arg paths.
6. **H4** after iBSS slice extraction.
7. H6 corpus family interleaves into whichever harness runs.

## 5. Triage & ledger

- `harness/triage/` (side-local): per-run machine-readable result
  (`seed-id, harness, config, outcome∈{ok,guarded-reject,fault,hang},
  pc at fault, fault-map`).
- Inventory (`artifacts/inventory.md`) records every corpus + result
  file hash — never committed.
- Verdict upgrade path: fault → minimal repro → second independent
  run → class-level doc note (Phase F style). Anything beyond
  class-level description does not leave the local machine and gets
  the coordinated-disclosure conversation first.

## Exit (per kickoff §8)

N harnesses living with executed-coverage maps; crash ledger triaged
(zero or known-crash items with verdicts). Only then Phase E device
sessions re-open, announcement-first.
