## Campaign v2 result set (verified from the ledger)

- **Bases: all 4 seeds decode byte-exact vs libcompression**
  (497,504 / 262,144 / 15,500 / 65,536 B) — the in-image engine and
  Apple's public reference agree bit-for-bit on every valid seed.
- **96 adversarial mutations: 0 engine faults, 0 hangs.** Every
  malformed input returned cleanly.
- Outcome classes over the 96 mutants (verified rows):

| class | count | content |
|---|---|---|
| clean reject | 39 | `written=0`: stream-magic kills (`bvxor@0`, SMC `@0x8`), truncations of single-segment seeds |
| full decode, ref-identical | 14 | flips fully tolerated (`bvxor@4/@6` …), output byte-identical to the base decode |
| full decode, content differs | 1 | `rnd sparse@0xed`: engine and reference agree on the decoded extent (63,496), bytes diverge at the damaged segment |
| partial stop, ref decodes | 28 | engine stops earlier (block/chunk-boundary); reference continues on the corrupted stream |
| partial stop, ref rejects | 14 | engine decodes a prefix of truncated / end-marker-less inputs the reference rejects outright |

- The 28 cross-implementation rows (reference still decodes, engine
  stops earlier): kind split **17 `bvxor` / 4 `headflip` / 7 `sparse`**;
  all engine-shorter (conservative), never engine-longer.
  - SMC stream: 14 rows, all stop at written = 128,052 (0x1f434).
  - Zeros-class synthetic: 14 rows, all stop at 207,744 (0x32b80).
  - Stop extents are fixed per seed regardless of corruption position —
    attributed (hedged) to framing/block-granularity rejects: a
    corrupted unit ends the stream at the previous unit boundary; the
    exact framing granularity is not resolved further here.
- The 14 engine-lenient rows (engine decodes, reference rejects): the
  engine accepts truncated streams and header-word flips without an
  end marker; the public reference requires the end marker. A flip
  pair 2–4 bytes apart inside the same header word can behave
  asymmetrically (one flagged as divergent, its neighbor fully
  decoded) — recorded as a data point, mechanism out of scope.

## Class-level corrections vs the in-flight report prose

1. Cross-implementation kind split: **17/4/7** (report prose guessed
   14/4/10 mid-campaign).
2. Dominant stop offsets: **0x1f434 ×21** (14 flagged + 3 SMC
   truncations + 4 SMC lenient flips) and **0x32b80 ×16** (6 flagged +
   2 lenient + 8 zro trunc/flip rows); the report guessed ×14/×14.
3. Truncations are *not* uniformly clean-rejects: single-segment seeds
   truncate to `written=0`, but SMC-stream truncations decode a
   128,052 B prefix (engine-lenient family).

## Findings (class-level)

1. **Engine robustness data**: no fault, hang, or memory-safety event
   across 96 adversarial inputs (96/96 clean returns). The channel's
   failure mode is "stop early / reject", never a crash, in this set.
2. **Byte-exact fidelity on valid inputs** through the runtime channel
   (`0x8a1`), cross-checked against an independent public
   implementation — the strongest substrate-fidelity result in Phase D.
3. **Cross-implementation difference dataset**: 28 + 14 rows, all
   graded safe (engine stops earlier on inputs both accept; engine only
   "accepted") — the dispatch channel is a boot-object decoder, not a
   general-purpose LZFSE stream coprocessor; behavior deltas are
   framing-granularity artifacts, class-level only.
4. **Follow-ups defined in the smoke report remain deferred** (VLC
   length-field desyncs; container-arm types on mutated containers) —
   none is required for the executed-coverage map above; H6
   (delta-bounded splices into the SMC stream) supplements the H2
   coverage in the same ledger discipline.
5. Cap discipline: H2 metrics are only meaningful with
   decoded-length-aware caps (base 40M/90 s, mutant 8M/30 s) —
   recorded so future reruns do not resurface the v1 artifact.
