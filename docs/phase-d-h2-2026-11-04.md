## Err (erratum, same day 2026-11-04 — budgets re-measured)

The 8M-insn mutant budget was still too small for the SMC-rate
classes: every "partial" row in the v2 table carries the ~6 s
8M-insn-budget wall signature, and a *no-op corruption* of the
pristine SMC stream (delta zero-slices, from the H6 campaign) at the
same cap writes exactly the 128,052 extent while the 40M-cap base
writes the full 497,504 — so 128,052/207,744 are **instruction-cap
watermarks, not decode stops** (the v1 cap lesson at 8M scale).

Re-measurement at sufficient budgets (200M insns / 75 s; companion
units `harnesses/h2_caprecheck.py` + `harnesses/h2_crosseval.py`,
ledgers `triage/h2-caprecheck-20261104-103659.json` +
`triage/h2-crosseval-20261104-104742.json` — 46 + 45 runs):

1. **42/42 flagged+lenient mutants terminate naturally**; no
   budget-bounds at 200M. All "partial stop" classes above were
   budget-bound executions, not engine behavior.
2. **The engine byte-matches macOS libcompression on every row the
   reference decodes** — all 28 former "cross-implementation"
   rows are byte-identical over the reference's extent
   (`ref_match=True`). The v2 flag came purely from comparing
   cap-truncated engine output.
3. Trailing-extent nuance: on 5 zeros-class `sparse` rows the engine
   emits 1–3 bytes **beyond** the reference's terminus (prefix still
   byte-identical) — the engine tolerates continuing where the
   reference stops; graded benign at this layer.
4. The **14 engine-lenient rows now complete**: the engine decodes
   truncated / end-marker-less inputs the reference rejects outright
   (one 1-byte-truncated stream and a truncated-last-word stream
   reach the full 497,504 extent). Engine-only outputs (no reference
   counterpart to compare).
5. The reference also rejects the SMC stream-head kills
   (`bvxor@0x0/@0x8` → written 0, wall ≈ 0) — implementations agree
   on the reject (earlier "clean-reject" rows for these were never a
   divergence).
6. The single v2 content-divergence row (`rnd sparse@0xed`) does not
   reproduce at full budget (byte-identical now, same extent, same
   regeneration) — ledgered as an irreproducible row per the
   reproduce-twice discipline.

**Net class-level picture (replaces finding 3): on all inputs both
implementations decode, the in-image engine is byte-exact against the
public reference; its leniency side accepts truncated/stream-tail
inputs the reference rejects; its expansion may overshoot the
reference terminus by ≤3 bytes. No fault class anywhere; the
"cross-implementation difference dataset" of the capped campaigns is a
measurement artifact.**

## Findings (class-level)

1. **Engine robustness data**: no fault, hang, or memory-safety event
   across 96 adversarial inputs (96/96 clean returns). The channel's
   failure mode is "stop early / reject", never a crash, in this set.
2. **Byte-exact fidelity on valid inputs** through the runtime channel
   (`0x8a1`), cross-checked against an independent public
   implementation — the strongest substrate-fidelity result in Phase D.
3. **Engine semantics vs the public reference (full budget)**: byte
   -exact wherever both decode; engine-lenient on truncated / tail-
   damaged inputs; ≤3-byte trailing overshoot on 5 corrupted-zeros
   rows; shared reject on stream-head kills. See §Err.
4. **Follow-ups defined in the smoke report remain deferred** (VLC
   length-field desyncs; container-arm types on mutated containers) —
   none is required for the executed-coverage map above; H6
   (delta-bounded splices into the SMC stream) supplements the H2
   coverage in the same ledger discipline.
5. Cap discipline: H2 metrics are only meaningful with
   instruction budgets far above the decode demand (the SMC class
   needs ~40M; mutants measured clean only at 20× that) and
   decoded-length-aware checks — recorded so future reruns do not
   resurface the v1/v2 artifact; wall-time-vs-budget is the
   discriminator of record.
