## 1. What H4 is

The ep0/DFU-mode "door" of the image: the request decoder that consumes
the USB control-transfer setup record and steers the DFU state machine
(DNLOAD/GETSTATUS/GETSTATE/CLRSTATUS-class), per the harness-spec
H4 charter ("I extracted parser, class-level only; no live probing").
Posture: full static decode of the decoder from real bytes + direct
register-passed emulation drives of the decoder function; no attempt to
drive the USB controller/supervisor layer (entangled; svc-gated).

## 3. Request grammar (byte-verified victim map)

Decoder fo 0x11caf8: full pacibsp frame; setup-record containment
`x1 ≤ x0 < x2`; `ldrb [x0,#1]` = bRequest; `ldrsb [x0]` = bmRequestType
(bit31 = to-host). `ldrh [x0,#6]` = wLength (little-endian halfword).

**To-device (bit31 clear)** — requires a data slot (x4 ≠ 0, else −1):
- bRequest 1 (DNLOAD): wLength 0 ⇒ accept: timeout `0x3200`, phase:=6,
  state:=6, block-len [+0x08]:=0; wLength 1…0x800 ⇒ accept: data-slot
  containment `x5 ≤ x4 < x6`, stamps a 0x20-B descriptor card at the
  slot, registers length at [+0x08], returns the length; wLength
  ≥ 0x801 ⇒ reject: timeout `0x320f`, returns −1, no writes (0x800 =
  2048 B = the image's ep0 DNLOAD block cap shape).
- bRequest 4 (CLRSTATUS-class): timeout := `0x3200`, received [+0x10]
  := 0, ctx-flag (+0x02) bit0 gates the failure-marker reset.
- anything else ⇒ returns −1, **no writes** (side-effect-free).

**To-host (bit31 set)** — x4 is not consulted (verified by
differential drives x4 = 0 vs slot: identical):
- bRequest 5 (GETSTATE-class): desc containment
  `base ≤ cursor < limit` over [+0x40/+0x48/+0x50] (breach = shared
  fatal tail), appends the current state byte at the cursor, finalizes
  with response length 1.
- bRequest 3 (GETSTATUS-class): folds a 6-B response card via checked
  copy (template 0x15b8c8, timeout/phase fields bound by reference);
  state == 6 ⇒ timeout `0x000bb800`, stays 7; state == 7 with
  received ≤ 15 ⇒ assert pair id 0x136 then 0x137 → shared fatal tail;
  staging pointer [+0x20] == 0 ⇒ the 0x137 pair; received ≥ 16 ⇒
  tail-position := received−0x10, checked copy appends the last 16 B of
  the staging buffer (w5 = 0x10), received := 0, timeout := `0x3200`,
  phase/state := 8; finalize length 6.
- anything else ⇒ returns −1, side-effect-free.

Finalize: desc 4-tuple from fo 0x23b9e8, deliver w0 = 0x80 with
response length 6 or 1, success epilogue returns 0. Handlers carry no
static callers (runtime slot registration — matches the prior recon's
event-slot dispatch boundary).

## 4. Emulation classes (ledger h4-ep0-20261101-085617.json)

Direct register-passed drives of the decoder; full entry (self frame)
plus two internal entries at fo 0x11cbf4 (post card-fold). Classes:

- **full-entry-smoke (2 runs)**: unknown requests, both directions:
  `ret −1`, zero writes.
- **getstate-append-verified (2 runs)**: the state byte lands at the
  desc cursor; run is x4-independent; the subsequent deliver step
  faults inside its call tree (fn 0x13766c+0x10, null-descendant
  read) — the record-binding boundary, not a decoder defect.
- **dnload-zero-accept / stamp-verified / dnload-cap-reject**: zero
  length accepted silently (state writes are in-extent and static-
  verified); 0x100-length run stamps the 20-byte card byte-exactly and
  returns the registered length; 0x801 request rejected with −1 and
  no writes.
- **card-fold-validator-boundary (4 runs)**: the GETSTATUS card fold is
  walled behind the record-kind validator (fn fo 0xd2de8: derefs
  [x0], kind ∈ {1,6} tests, bit35 checks); plausibly-correct register
  shapes that satisfy the decoder's own containment arithmetic fail
  the record contract (flat-cursor priming is not the record system's
  input format). The 0x136/0x137 asserts are therefore NOT reached in
  the full-entry mode.
- **post-card-arc / footer-arc (2 internal-entry runs)**: bypassing the
  card fold, the decoder's own post-card logic executes: the assert
  pair fires (block-trace of the assert-family body sites) and the
  footer-copy walk executes its auxiliary chain but performs no
  tracked writes before the record gate rejects it.
- **shared-fatal-tail continuation artifact (3 runs total)**: breach,
  asserts and mediator tails all return in bare emu, fall into the
  next function's prologue with garbage registers, wander ~57 distinct
  blocks and self-spin at the early pre-pacibsp cluster (fo 0x4c8)
  until the instruction cap. Single class, artifact of the missing
  svc/gate substrate; in silicon these tails are assumed
  non-returning. Not a device fact.

## 5. Boundary: what was deliberately not driven

- The USB controller/service layer (endpoints, event slots): runtime-
  registered; static reach ends at the slot table (prior recon §2.9
  carries it forward).
- The record/descriptor system (templates 0x188728/0x188b70/0x188ea0/
  0x188ee8 and their kin): the state object's desc fields are built at
  boot by the initializer (fo 0x11c294, driven from the USB bring-up
  callers 0x86cb4/0x86d90 with template 0x188b70). Decoding the
  initializer's recipe remains open work (the follow-up arc if budget
  allows); until then the card-fold/deliver paths are boundary-only.
- The DFU OUT data-stage acceptance chain's internals (fo 0x11cd18):
  only reached as the post-tail artifact; its svc gate and grant check
  are prior-recon territory (grant chain 0x119160 → 0x7e60c, default-
  rejecting empty interval — recron carried from 2026-10-27/28).

## 6. Robustness verdict

1. The request decoder itself shows a **uniform reject discipline**:
   every unmatched request or bound violation returns −1 with zero
   writes; the DNLOAD cap (0x800) is enforced with a distinct timeout.
2. The only input-reachable escape from clean behavior is the
   **GETSTATUS state-7 assert tier** (short inconsistent response card:
   asserts 0x136/0x137), emu-confirmed by block trace. It guards
   protocol-broken short uploads with a design-fatal mediator — not
   tunable toward controlled effects, no exploit-class surface.
3. GETSTATE appends the state byte and DNLOAD stamps the descriptor
   card verifiably — the parser mechanics are sound; the walls live in
   the record/descriptor binding system (§5), as expected for a
   type-tagged initialization framework.
4. H1 (typer grammar), H2 (compression), H3 (registration paths) and
   H4 (request grammar) together show: input-reachable fault classes
   in this image are guards and asserts, all terminating in design-
   fatal tails; no parser-controlled write primitive surfaced in any
   harness.
