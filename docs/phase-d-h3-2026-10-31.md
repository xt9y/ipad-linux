## 1. What H3 is

The `memboot` and `go` console-verb handlers (the hidden registration-
keyed units) and their upstreams: key-blob estate, registry walk, and
the call-site event recorder both verbs call. Objective per spec: the
arg/key input grammar and the guard/reject topology of the registration
paths — as classifiers, not execution engines.

**Posture (decided up front):** bounded emulation of the one fully
self-contained unit (the call-site event recorder) + an
instruction-verified static class-map of both verb guard chains. Full
verb-tail execution was deliberately not attempted: the registration
tail is entangled with a lock family, a service-context chain and the
same SoC register source that stops bare drives (§7), so an executed
tail would measure the substrate, not the grammar.

Corrections against the prior recon / this session's own interim notes
(with the Phase F rule: every prior-recon name below was re-established
from real instructions before use):

1. **`0x12e518` vs `0xe2518`** — the recon's "memboot tag lookup via
   `0x12e518`" is the VA-tail form of `0x1fc12e518`; read as a fileoff
   it points at the wrong function. Fileoff `0x12e518` (VA
   `0x1fc17a518`) is a separate constructor (see below), not a memboot
   callee. The real callee is the recorder at fileoff `0xe2518`.
2. **The poison-sentinel constructor (fileoff `0x12e518`)** — writes a
   record whose `[+0x58]` pair = `{registry root 0x1fc1a5bb8, sentinel
   0x00BAD0001FFFF0000}`, `[+0x40]` = template `0x1fc1e8d94`, guarded by
   an entry containment check `x0 ∈ [x1, x2)` → error `0x1fc17a624`.
   Unrelated to the verb callee; kept here only to close the alias.
3. **`0xe6a0` is not the `go` key getter** — fileoff `0xe6a0` is an
   unrelated 32-byte-stride table-scan loop. The actual `go`-side call
   is VA `0x1fc04e6a0` = fileoff `0x26a0`, a pure thunk that ignores
   `x0` and materializes `x3 = registry root`. There is no "key blob
   getter" call; the key is passed as an address range (§5).
4. **Out-array pointer is `0x159bd0`** (digit-swap error `0x15abd0` in
   the interim notes).
5. **The `go` error references `0x1e31b8` / `0x1e31e8` are not strings**
   — they are rows of the tag-triple table itself (§5); the error path
   hands table rows to the mediator, not string constants.
6. **Token `0xc58c` is fileoff `0x58c`** (VA-tail alias); it is a
   `tail-b` to fileoff `0x438`, an SoC system-register read.
7. **`go`'s "deeper call `0xd2390`" is VA-tail** of `0x1fc0d2390` =
   fileoff `0x86390` — the IMG4-band callee already named in the kickoff
   digest (`0x82054/0x86390`), not fileoff `0xd2390`.

## 3. Verb dispatch surface (static class-map)

From the noun-row family and dispatch tails (all numbers dual-form in
§2):

- **Name pool** fileoff `0x210750..0x21075e`: `"bootx"`, `"memboot"`,
  `"go"` (4-char names inside a pool at `0x21xxxx`).
- **Noun rows** fileoff `0x15b1e8–0x15b3b0`, consisting of
  `{name ptr+len ×2, root-record fn 0x159bb8, packed handler word
  0x80f0000000001164 (memboot→fn 0x1164) / …183c (go→fn 0x183c),
  sibling fn 0x15a9d8, counters 0x226a00–a02}`. `bootx` sits apart as
  special row `0x15b180` (packed `0x40000001` family = vendor `0x40`
  bRequest 1 binding, prior recon).
- **Early registration table** fileoff `0x15b350` / `0x15b380`
  (0x30-stride rows, `nvme_firmware0` / `spi_nand0`), populated through
  the helper family reached from fn `0x6c0`.
- Handler signatures (harness sig-check anchors): both heads are
  `pacibsp`-prologued; memboot immediately routes its LR through the
  `0x2790` trampoline; `go` opens `sub sp, #0xf0`.

Both verbs are **registration-keyed**: without a registered boot object
they exit silent/zero (`go` state gate §4.7; registry walk §6.1).

## 4. Verb guard chains (verified instruction class only, not executed)

### 4.1 `go` handler (fileoff `0x183c`)

Ordered chain, each step `bl`-verified:

1. context probe (`0x264c`), then the *first key range* built as
   registers: start = `0x1e31af`, end = start+9 (via `0x26a0` thunk,
   which only sets `x3 = registry root`);
2. `bl 0xc46c0` registration walk → returns a row handle;
3. **handle validation, two distinct reject rows**: `cbz handle` →
   reject row `0x1e31b8`; `cmp handle, 0x02000001` (`b.lo continue`) →
   reject row `0x1e31e8`. Both rows are table entries handed to the
   shared reporter (fo `0xda8c`). Handle space is `[1, 0x02000000]`;
4.  grant band `bl 0x3283c`, grant check `bl 0x7e60c` with the **handle
    in `x4`** (`w0` bit0 = ok; reject → the reporter entry at fo
    `0xda84`);
5.  deeper call into the IMG4 band: VA `0x1fc0d2390` = fileoff
    `0x86390`, then the *second key range* `0x1e31ff` (+4)
   through `0x26a0` again → `bl 0x724fc` key→object resolve
   (`cbz` missing → reject), sign-bit validity checks (`tbnz #31` →
   reject); additional chain `0x81b40 / 0x82054 / 0xc3c58 / 0xcab6c`;
6. out-array built through `0xe2bc0` with template `0x159bd0`
   (`x24`) and three stack-local pointer groups;
7. **state gate** on FO `0x226a08`: byte0 must equal 1 **and**
   `[state+0x38] ≠ 0`, else reject;
8. env keys `0x69626474`, `0x6b726e6c` (4-char packed words) resolved
   per-call (`0x82058`; missing → reject; `0xcab6c` sign check);
9. **pointer-arithmetic guard before any synthesized address**:
   `end−start` computed with `subs`, the handle compared
   `cmp handle, end−start` (`b.hi` → shared guard-fail block fo
   `0xdb58`), and only then `add x6 = arg0 + handle`. No unguarded
   `base + handle` path exists in the chain;
10. final invocation `bl 0x272bc` (7-arg, three stack pointer pairs),
    context thunk `0x2758`, success path returns `w0 = 0`.

Reject classes (all clean returns / mediator lines, never faults):
handle-null, handle-overflow (≥0x02000001), grant-fail, key-object
missing, sign-bit invalid, state-object uninitialized (byte0 or +0x38).

### 4.2 `memboot` handler (fileoff `0x1164`)

1. trampoline prologue (`0x2790`), context probe (`0x264c`), workspace
   init `0xd29c0` (0x200 bytes on the `sp+0xf0` stack buffer);
2. tag constant `w0 = 0x3c427478`, `w1 = 0` → `bl 0xe2518`
   (the event recorder — see §6);
3. zero-thunk `0x26d4`, grant band `0x3283c`, grant check `0x7e60c`
   with **`w4 = 0x1e000000`** (a grant class different from `go`'s
   argument-derived `w4`);
4. `tbz w0, #0 → fileoff 0xd3c4` — reject exit is the **shared error
   tail**, not a per-verb row (topology difference vs `go`);
5. then `0x281c`, constant `0x5a6` stored with `x25`, `0x2720`, the big
   setup `bl 0xcfdfc`, and a 7-pointer argument build
   (`x8..x13` = stack-local pairs, `x14 = template 0x159bd0`).

### 4.3 Registration walk (fileoff `0xc46c0`, head verified)

Lock discipline (`bl 0xc58b4` grab / `0xc586c` release) around lock
state `0x236910`, list ops `0xd67a8` / `0xd69a4` on a `0x28`-stride
head, then the row *find* with the containment check `x0 ∈ [x1, x2)`
and row record at `[row+0x60]`; row-not-found → unlock and **return 0**
(this is the registration-keyed silent exit at the walk level). Row
flag field `[row+0x14]` must be non-zero where checked in this family.
Intentionally **not executed** (§7) — internals beyond the head are
class-mapped only.

## 5. Key estate: the tag-triple table (the "blob keys" decoded)

Fileoff `0x1e31a0..` is a **tag/len/value triple table**, not a blob
archive. u32 little-endian stream, 12-byte stride after a 16-byte
perturbed head:

```
[0x0000801f, 0x00000004, 0x20000020]   head row  (with 0x00070007, 0x00040004)
[0x20000028]  then 0x20000030 .. 0x20000060   — trailing {0x0000801f, 4, value} triples
…terminating 0xffffffff run
```

The `go` verb's two "key blobs" are **byte-range fragments over this
table**, not standalone blobs: `start = 0x1e31af` (+9) and
`start = 0x1e31ff` (+4) — the second is the first plus 0x50 (two
12-byte units). They are passed as `(start, end, registry-root)`
to the walk of §4.3, which bounds them by the containment check and
treats the fragment start as a row cursor (row fields `[+0x14]` flag,
`[+0x60]` record). Grammar shape of the verb key argument:
**an in-table byte range with row-relative fields, validated by
containment, not content**.

## 6. The call-site event recorder (fileoff `0xe2518`, VA `0x1fc12e518`)

The one self-contained unit, fully decoded and emulated.

### 6.1 Semantics (from instructions)

- **Entry stub rotates arguments**: `x2 = x1; x1 = x0; x0 = x30;
  xpaci x0` — on entry the caller's `x30` is captured as the
  "caller" field, the original `x0` becomes the tag, the original
  `x1` the argument. (A *record-later* convention: the caller address
  travels through the call.)
- **State**: three qwords at `0x224268` `{start, cur, end}`;
  file-time values `start = cur = 0x1fc283568`,
  `end = start + 0x4000` — the arena is the in-frame zero-mapped tail
  beyond file end; the 32-bit **counter** lives at `[start+4]`.
- **Containment**: proceeds only if `start ≥ cur` **and**
  `start < end` (`cmp/ccmp/b.hs` pair, decoded both branches). With the
  file-time state (`start = cur`, empty log) this reduces to
  `start < end`; a zero state fails the second half and exits through
  the mediator — matching run F.
- **Cap**: `cmp w9, #0x2a9; b.hi drop` — counter > 681 → **silent
  drop** (return without insert, no log line, `x0` = captured caller).
- **Slot arithmetic**: `slot = start + 0x10 + 24·counter` computed with
  `adds`, carry → mediator `0x13a2a0`. Reachability: the counter is
  already capped at 681 when the math runs, and 24·681 never carries in
  64-bit — the carry is **state-dependent only, not argument-reachable**.
- **In-region guard**: `slot < end` shaped as `cmp x24, x23;
  ccmp x22, x23, #0, ls; b.ls mediator` → violation → mediator `0x13a40c`
  `+` cross-frame tail, clean return.
- **Token**: `bl 0x58c` → `b 0x438` → `mrs x0, s3_4_c15_c10_5` — a
  SoC system-register read (neighbours `cntp_tval_el0`, `cntfrq_el0`):
  the record's first field is a **hardware register stamp**, not a
  software counter.
- **Record**: 24 bytes `{token, caller}` then `{tag:u32, arg:u32}` —
  stored `stp x0, x21, [slot]` / `stp w20, w19, [slot+0x10]`.
- **Arena budget**: extent 0x4000 = 16,384 B admits 682 records
  (24·682 = 16,368); the count cap is 681. The recorder is
  **dual-bounded**: a count cap *and* an extent assert. The 681/682
  boundary is static-verified only — a single-input-window drive
  cannot prime the in-plane counter word (see §7).

Notes:
- **Fault class `soc-token-chain-mrs`** — the recorder's token is an
  SoC register read; full-entry drives stop there in a bare substrate.
  Not a parser defect; it is the boundary of what a classifier may
  observe without modelling the register.
- **pc = 0 in G** — the internal entry pops `x30` from the untouched
  zero stack (no frame planted); synthetic-drive artifact, deliberately
  documented instead of masked; the record bytes are the verdict.
- **Two reject tiers, distinct**: cap-overflow drops silently (no write,
  no log, `x0` = caller value); extent/containment violation rejects
  through the mediator (one log line) and returns 0. Both are clean
  program flow — neither faults.
- The 0x13a40c "mediator" is a **message-line emitter that returns**
  (stages a pool string, calls the print-side family), not a
  processor stop — verified from its head instructions and by the F
  run returning.

## 7. Boundary: what was deliberately not driven

- Full `go` / `memboot` verb tails (registration semantics end-to-end):
  entangled with the lock family (`0xc58b4/0xc586c/0xc5844/0xc55b4`),
  list ops (`0xd67a8/0xd69a4`), service context and the SoC register
  token; executed tails would measure the substrate. Static
  class-coverage only.
- The cap-681 boundary (counter 681 vs 682) and the carry-guard of the
  slot arithmetic are **state-dependent** paths: the single-input-
  window drive cannot prime the in-plane counter word beyond the
  `aa_guard` prefill, and 24·681 never carries. Static verdict stands.
- The recorder's *consumers* (what reads the log) are out of scope for
  H3; the H4 iBSS USB arc work proceeds without them.

## 8. Robustness verdict

The hidden-verb entry surface is **well-bounded at the class level**:
every argument crossing is guarded (containment, handle range
`[1, 0x02000000]`, grant gate, state gate, pointer-arithmetic guard
before `base + handle`), and the one reachable arithmetic overflow
site (recorder carry) is protected and argument-unreachable. Both
reject tiers are graceful. The interesting structure for later phases
is the registration-keyed silent-exit and the dual-bounded log family,
not an input fault class. Combined with H1's closure (only the
outermost zero-value guard input-reachable) the console-side surface of
this iBoot build shows **no argument-triggerable fault class** in the
units decoded under H1/H3 so far.
